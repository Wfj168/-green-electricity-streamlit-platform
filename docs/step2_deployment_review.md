# 步骤2复盘：部署与演示链路

## 结论

本阶段门禁通过。平台已明确区分两种运行方式：

- Streamlit Community Cloud或本地单进程只启动前台，自动进入单机演示模式；实时计算、图表、指标、绿电直连测算和导出保持可用。
- Docker或服务器完整部署启动UI、API和Worker，启用项目版本、后台任务、历史结果、认证与持久化。

## 现场复现

2026-07-18对现有Community Cloud地址进行浏览器级检查：

1. 首次访问显示应用因长期无访问进入休眠，而不是持续性Python异常。
2. 执行唤醒后，页面标题恢复为“园区低碳规划与绿电直连优化平台”。
3. 内层应用成功渲染平台概览、当前状态和8个导航页面。
4. 由于Community Cloud未部署独立API，“项目与任务”应进入单机演示模式，这是设计内的安全降级。

冷启动期间可能短暂显示加载骨架；演示前应至少提前2分钟访问并完成一次页面切换。

## 本阶段实现

- 新增环境与权限部署前检查，覆盖Python版本、后台地址、令牌配置、数据目录和认证模式。
- 后台地址不完整、包含凭据或包含查询参数时，前台在发起网络请求前阻断并显示可执行提示。
- 后台成功返回非JSON内容时转换为受控错误，避免页面未捕获异常。
- 单机演示不再显示为“原型故障”，页面明确说明可用范围和完整部署条件。
- 依赖增加主版本上限并显式声明`requests`，降低云端自动升级造成的部署漂移。
- CI增加部署前检查，保留测试和镜像构建门禁。
- 部署文档补充Community Cloud与完整部署的差异、Secrets规则和严格检查命令。
