# 园区低碳规划与绿电直连优化平台 v0.7.0 项目交接手册

## 1. 文档用途与交付结论

本手册供产品负责人、算法工程师、后端工程师、前端工程师、测试人员和运维人员共同交接。它描述平台当前真实能力、逐页面操作、模块实现、算法口径、数据结构、部署运维、验证方法和扩展边界。

v0.7.0已经形成四个闭环：用户可在前台直接完成单会话计算；完整部署下可保存项目和场景版本、提交后台任务并读取历史结果；两类模型通过统一服务执行并导出可追溯成果；运维侧具备检查、日志、指标、审计、备份、恢复和回滚基础。

当前版本适合演示、研究验证、方案筛选、受控内网试点和单服务器项目交付。它不替代配电网潮流、短路电流、继电保护、接入系统审查、设备选型和施工图设计，也不应被描述为已经实现跨主机高可用。

## 2. 产品定位与使用对象

平台面向园区综合能源规划与运行决策，支持两种模型模式。

1. 快速电力滚动调度：关注光伏、风电、气电、电网和电储能的运行，适合快速演示、参数敏感性分析和小时级电力调度。
2. V17综合能源规划：关注电、热、冷、气、储能、柔性负荷、碳约束、绿电直连和P2X/绿氢，适合技术组合筛选、典型日规划和S0—S8政策场景比较。

典型用户包括园区能源管理人员、规划咨询工程师、科研团队、低碳项目负责人和系统交付工程师。

## 4. 系统架构与运行链路

### 4.1 前台直算链路

用户在“参数配置与运行”提交表单，页面把参数转换成稳定载荷。`UnifiedModelService`按`model_kind`路由到快速调度或V17适配器，返回统一的成功状态、错误结构、元数据、摘要、指标、表格和ZIP成果包。结果保存在当前Streamlit会话，后续页面只读取本次结果，不使用固定演示数字。

### 4.2 完整后台链路

UI通过`PlatformApiClient`创建项目和场景版本，再提交优化任务。API只登记任务，不在请求线程执行求解。Worker原子领取任务并续租，调用统一模型服务，成果包写入文件存储，摘要、指标、校验和与任务状态写入数据库。用户随后可以读取任务和结果。

### 4.3 部署形态

| 形态 | 组成 | 可用能力 | 限制 |
|---|---|---|---|
| Community Cloud演示 | Streamlit UI | 两类模型直算、图表、指标、比较、导出 | 没有独立API时项目版本与后台历史关闭 |
| 本机开发 | UI、API、Worker、本地SQLite | 完整业务闭环 | 仅供开发或受控演示 |
| 单节点交付 | Docker Compose、持久化卷、令牌认证 | 完整闭环、任务可靠性、日志、指标、备份恢复 | 不是跨主机高可用 |
| 后续高可用 | 多实例API、PostgreSQL、Redis、对象存储、SSO | 目标架构 | 当前仓库尚未实现 |

## 5. 通用页面规则

侧栏顶部的“模型模式”决定导航与页面数据源。快速模式有9页，综合模式有10页。修改任何配置后都必须重新运行；侧栏状态卡只表示当前会话最近一次成功结果。刷新浏览器会清空单会话结果，但完整后台部署中的项目、场景、任务和成果仍保存在数据库与成果目录。

参数指纹是对规范化载荷计算的SHA-256摘要，用于判断两次场景输入是否一致。指纹不是安全签名，也不替代数据库版本号。

## 6. 逐页面交接说明

### 6.1 平台概览

页面目标：解释平台定位、当前模型状态和从模型选型到决策交付的四步流程。

操作方式：先在侧栏选择模型。若已有当前会话结果，页面展示四张关键指标卡；没有结果时提示进入配置页。

实现方式：`overview_page`读取会话中的`simulation_result`或`integrated_result`。快速模式展示用电量、绿电占比、碳排和综合成本；综合模式展示年度碳排、年度购电、弃电率和多能服务率。

讲解重点：这是决策流程入口，不是静态驾驶舱。所有指标都来自当前求解结果。

### 6.2 项目与任务

页面目标：保存项目、版本化场景、提交异步任务、查看状态和读取持久化结果。

前置条件：需要配置可访问的`PLATFORM_API_URL`。Community Cloud只部署UI时，本页显示“单机演示模式”，这是设计内的安全降级，不是故障。不能把云端的后台地址配置为`127.0.0.1:8000`。

完整操作：创建项目，选择项目，确认模型和参数指纹，输入场景版本名称，点击“保存场景并提交后台计算”。任务记录显示排队、运行、成功、失败或取消。成功后可以读取结果；排队或运行时可以取消。

实现方式：API分别保存`projects`、`scenario_versions`、`optimization_jobs`和`optimization_results`。同名场景在项目内自动递增版本。任务请求记录模型类型；Worker调用统一模型服务。`idempotency_key`用于网络重试去重，`worker_id`和租约用于并发控制。

常见问题：后台地址无效时页面停止调用该地址；后台不可用时不影响其余单会话页面；只读用户不能创建项目或任务；任务失败时优先查看`error_code`、`error_message`和结构化日志中的`job_id`。

### 6.3 参数配置与运行：快速电力滚动调度

页面目标：建立园区电力边界并运行滚动线性优化。

基础场景参数包括场景名称、年用电需求、规划周期、滚动天数、购售电均价、交换容量上限和电价分布国家代码。约束包括最低绿电占比、年度CO2上限、最大弃电率，以及是否允许自动规划和限制投资规模。

设备与价格表分为电源、储能、燃料价格和投资成本。用户可以下载8760小时CSV模板，也可以上传时序数据；未上传时系统生成可复现的负荷、风光出力系数和电价曲线。

点击“开始实时优化调度”后，页面先执行输入和表格校验，再进行容量预规划和滚动求解。失败时通常需要放宽RPS、CO2或CEEP约束，或提高电网交换容量。

实现方式：页面构建`StoreMoreInputs`与四张参数表，`SimulationService`校验后调用`run_storemore_simulation`。求解器为SciPy HiGHS线性规划。

### 6.4 参数配置与运行：V17综合能源规划

页面目标：选择S0—S8模板，并配置电、热、冷、储能、柔性负荷、碳、绿电直连和P2X。

运行口径包括60/30/15分钟分辨率与可复现随机种子。设备页给出光伏、风电、热电联产、热泵、电制冷和燃气锅炉容量上限；储能页控制电储能与蓄热；柔性负荷页控制日内转移和可中断负荷；碳页控制相对S0排放上限与碳成本；绿电直连页控制园区绿电、直连目标和新能源利用率；P2X页控制电解槽与工艺热替代。

页面先把模板与覆盖项合并成`integrated-planning-v1`载荷，再执行范围和跨字段依赖校验。只有没有错误时才调用V17模型。较高分辨率显著增加求解时间，现场演示建议60分钟。

实现方式：`IntegratedPlanningConfig`负责默认值、验证、载荷与参数指纹；`UnifiedModelService`调用`run_quick_trial`，后者经`model_adapter`进入V17 LP/MILP核心。

### 6.5 数据与预测

页面目标：建立15分钟数据质量、预测评估、日前预测和日内滚动请求的最小闭环。

操作顺序：下载模板或加载14天示例数据，检查数据点、间隔、错误与质量状态；通过后点击“评估基准并生成日前96点预测”；查看MAE、RMSE和sMAPE；最后选择R0—R4运行场景、滚动窗口和最新电/热储能SOC，生成日内请求JSON。

必填列为`timestamp`、`electric_load_mw`、`pv_available_mw`、`wind_available_mw`和`electricity_price_cny_per_mwh`。可选列包括热负荷、冷负荷和温度。数据必须严格15分钟、时间递增、无重复、关键数值可解析、负荷和可再生功率非负。

实现方式：数据契约把错误定位到字段、CSV行号和时间戳。预测服务比较前一日同一时刻的季节朴素法与最近96点均值法，按验证集MAE选择模型。日前输出固定96点并生成由算法、训练截止和预测起点决定的版本号。日内请求继承该预测版本和最新SOC。

边界：当前预测是透明基准框架，不是训练复杂机器学习模型；接入LSTM、LightGBM或天气预报前，仍需保留同一训练/验证切分和基准对照。

### 6.6 实时结果图

适用模式：快速电力滚动调度。

页面内容：电力调度图展示负荷、风光、气电及购售电；储能图展示充放电与SOC；平衡图用于检查供需；购售电响应图把电价和电网行为放在同一时间轴；展开区提供逐时明细。

实现方式：页面读取本次`dispatch`表并用Plotly绘图。图表不再求解模型，也不缓存固定结论，因此更改参数后必须回到配置页重算。

检查要点：供需误差应接近数值容差；SOC必须处于上下限；高价时段通常减少购电或增加放电，但约束可能改变这一行为。

### 6.7 多能流结果

适用模式：V17综合能源规划。

页面内容：先选择带年度权重的典型日，再查看电平衡、热平衡、冷平衡和储能状态。下方标签页提供容量、多能调度、成本、碳排和诊断原始表。

实现方式：V17使用典型日与`day_weight`折算年度结果。页面按`day_id`过滤调度表，只改变显示，不重新求解。容量表来自规划变量，成本与碳排表来自后处理，诊断表包含平衡误差、求解器状态和边界使用情况。

检查要点：解释年度指标时必须包含典型日权重；不能把单日曲线直接相加当作年度总量。

### 6.8 调度综合指标

适用模式：快速电力滚动调度。

页面内容：关键指标卡、指标柱状图与明细表、RPS/CO2/CEEP约束执行检查、各滚动窗口目标值和末端SOC、容量规划结果。

实现方式：指标由调度表聚合。CO2年度上限按本次滚动小时数折算为模拟期上限；约束检查用小容差比较目标与结果。

讲解重点：滚动日志证明模型不是一次性静态求解，末端SOC从一个窗口传到下一个窗口。

### 6.9 综合规划指标

适用模式：V17综合能源规划。

页面内容：年度碳排、购电、弃电率和服务率；指标按能源、经济、环境、可靠性、园区与P2X分组；“全部”页保留完整指标；执行追溯显示摘要与模型元数据。

实现方式：统一模型服务把V17指标表转换为键值指标，同时保留原表。页面按指标英文名称的稳定模式分组，不修改数值。

检查要点：区分私人年成本、碳外部成本、社会总成本和目标函数成本；只有启用碳价内化时碳外部成本才进入优化目标。

### 6.10 S0—S8场景对比

适用模式：V17综合能源规划。

页面目标：以相同时间分辨率和随机种子逐个真实求解选择的场景，不使用静态对比数据。

操作方式：选择场景，演示时用60分钟分辨率，点击“运行真实场景对比”。页面给出成功数量、最低成本、最低碳和最大减排场景，绘制成本碳排图与成本—碳排前沿，并可下载总表和各场景原始ZIP。

实现方式：`ScenarioComparisonService`逐一调用`UnifiedModelService`。以成功的S0为基准计算减排量、减排比例、成本变化和平均减排成本。若某场景失败，其错误保留在总表与清单，不用占位值替代。

### 6.11 绿电直连规划

快速模式下，页面把当前滚动期用电量和绿电量按滚动天数折算为年度，计算目标绿电量与缺口。用户输入规划期、三类电源成本、损耗和固定工程费，系统比较园区内新增、虚拟电厂聚合和绿电基地专线三类方案。

综合模式下，页面直接读取V17内生结果中的园区绿电、直连、P2X和电解槽指标，并比较V17输出的三类年度成本，不使用页面固定数字重算模型结论。

实现方式：快速模式由`GreenDirectService.evaluate`计算，综合模式由`from_v17_metrics`映射结果。最低成本只是经济筛选推荐，工程落地还需要电网接入、土地、线路走廊、合同和可靠性评估。

### 6.12 结果导出

快速模式导出输入摘要、使用的时序、调度、投资、指标、滚动日志和图。综合模式导出容量、调度、成本、碳排、指标、诊断、输入曲线、场景定义和执行清单。

实现方式：成果包包含平台版本、模型版本、场景摘要和执行元数据。后台保存时额外记录URI和SHA-256，用于检查文件是否被修改。

交接要求：任何对外结论都应和原始成果包一起归档；不要只保存截图。

### 6.13 工程架构

页面目标：向非开发人员解释交互、应用服务、双模型、项目任务和运维模块，以及核心算法和严谨性边界。

实现方式：页面内容与本手册一致，算法列表同时覆盖快速调度、综合能源、预测、场景比较、绿电直连和任务可靠性。

## 7. 算法实现说明

### 7.1 快速调度线性规划

每个时段的主要变量包括光伏出力、风电出力、气电出力、电网购电、电网售电、储能充电、储能放电、SOC、弃电和缺电。目标函数最小化燃气成本、购电成本、储能使用成本、弃电惩罚和缺电惩罚，并扣除售电收入。

电力平衡可概括为：风光实际出力 + 气电 + 购电 + 放电 + 缺电 = 负荷 + 充电 + 售电 + 弃电。

设备变量受可用出力、额定容量和电网交换上限约束。SOC递推为：本期SOC = 上期SOC乘以保留率 + 充电乘以充电效率 - 放电除以放电效率。第一时段使用继承的初始SOC。

RPS约束限制风光发电量相对供能规模的最低比例；CO2约束用气电出力乘排放因子并按模拟小时折算年度上限；CEEP约束限制弃电量相对负荷的比例。求解使用`scipy.optimize.linprog`的HiGHS后端。

### 7.2 48小时滚动时域优化

模型为每个运行日构建48小时预测窗口，只保存前24小时为已执行结果。保存段最后一个SOC作为下一窗口初始状态。若运行N天，则产生N个滚动窗口和24N小时最终调度。

这种做法同时保留对次日状态的前瞻和跨日储能连续性。窗口目标函数值用于诊断，不应直接相加解释为全生命周期成本，正式成本以最终保存调度和投资口径汇总。

### 7.3 快速容量预规划

容量预规划根据年需求、现有容量、投资开关和上限生成光伏、风电与储能增量，再把规划容量送入滚动运行。它用于快速决策，不等同于V17把全部规划与运行变量联立求解的综合容量优化。

### 7.4 V17综合能源LP/MILP

V17同时包含规划容量变量和典型日运行变量。容量包括光伏、风电、CHP、热泵、电制冷、燃气锅炉、电储能能量与功率、蓄热能量与功率，以及启用时的电解槽。

运行侧联立电、热和冷平衡。CHP把燃气转换为电与热，热泵用电供热，电制冷用电供冷，燃气锅炉供热，电储能与蓄热跨时段递推，柔性负荷执行日内能量守恒，可中断负荷承担高惩罚成本。非关键负荷允许以VOLL表示的高成本缺供，关键服务和年度EENS约束保证可靠性口径。

年度目标由资本回收因子折算的年化投资、固定运维、燃料、购售电、需量、储能退化、柔性负荷、弃能、缺供和其他运行成本组成。碳价内化开启时加入碳外部成本；结果同时报告私人年成本、社会年成本和目标函数成本，避免混淆。

线性场景使用HiGHS LP。启用严格充放电互斥或购售电互斥等离散约束时使用HiGHS MILP，并受时间上限和相对间隙控制。

### 7.5 典型日与年度折算

V17输入中的每个典型日带`day_weight`。时段能量先乘时间步长，再乘典型日权重汇总为年度量。容量变量不乘权重。多能流页面展示单个典型日，指标页面展示加权年度结果。

### 7.6 S0—S8定义

| 场景 | 核心变化 | 主要用途 |
|---|---|---|
| S0 | 无碳上限、无储能、无柔性负荷 | 基准系统 |
| S1 | 碳上限与碳成本 | 低碳约束影响 |
| S2 | S1加电储能和蓄热 | 储能贡献 |
| S3 | S1加可转移负荷 | 柔性负荷贡献 |
| S4 | 碳、储能、柔性负荷协同 | 核心源荷储场景 |
| S5 | 偏远低空负荷、本地新能源和孤岛保障 | 韧性增强 |
| S6 | 产业园绿电、利用率和更严碳约束 | 净零园区筛查 |
| S7 | 低空、园区、微电网、绿电直连综合 | 综合展示场景 |
| S8 | 更严绿电与碳配额，内生P2X/绿氢 | 深度脱碳场景 |

### 7.7 P2X与绿氢

启用内生P2X后，电解槽容量、逐时用电、绿氢产量和氢替代工艺热进入优化变量与约束。电解槽耗电受容量上限和可再生电量占比限制；氢产量由单位制氢电耗换算；替代热量由氢低位热值和锅炉效率换算；避免的燃气排放按替代热量、锅炉效率和燃气排放因子计算。

该模块是园区规划筛查，不是详细氢网络、储氢安全或设备动态模型。

### 7.8 预测基准与评估

季节朴素预测取前96个15分钟点的同一时刻值。近期均值预测取最近96个点的均值。验证集默认最近7天，共672点。

MAE是绝对误差均值；RMSE是平方误差均方根；sMAPE使用实际值与预测值绝对值之和进行对称归一化。平台先按MAE、再按RMSE排序选择基准。预测版本由算法、目标、训练截止、预测起点和96点范围的规范载荷生成。

### 7.9 场景比较与平均减排成本

相对S0减排量 = S0年度CO2 - 当前场景年度CO2。减排比例 = 减排量 / S0年度CO2。成本变化 = 当前社会年成本 - S0社会年成本。只有减排量为正时才计算平均减排成本：成本变化 / 减排量。

### 7.10 绿电直连成本

年度目标绿电 = 年用电量乘目标绿电占比。年度缺口取目标绿电减当前绿电与0的较大值。考虑损耗后需采购电量 = 缺口 / (1 - 损耗率)。规划期成本 = 需采购电量乘LCOE乘规划年数，再加固定工程费。系统在三类方案中选择成本最低者。

### 7.11 任务租约、幂等和失败恢复

项目与幂等键组成数据库唯一索引。Worker在`BEGIN IMMEDIATE`事务中领取最早排队任务，并同时写入所有者、租约截止和尝试次数。运行期间定时心跳续租。租约过期且未达到最大次数时重新排队；达到上限时标记`WORKER_LEASE_EXPIRED`。完成或失败写入必须匹配当前Worker，防止旧进程覆盖结果。

### 7.12 备份、恢复与完整性

备份使用SQLite在线备份接口复制一致性数据库，再与成果文件写入ZIP。清单记录平台版本、时间、文件大小和SHA-256。验证同时检查危险路径、ZIP损坏、文件大小、校验和与`PRAGMA integrity_check`。

恢复前必须停止API和Worker。覆盖已有数据库时系统先创建`pre-restore`回滚包，再用同目录临时文件原子替换数据库。

## 10. 部署、发布与回滚

### 10.1 发布前

1. 从`.env.example`生成部署环境配置，替换密钥，不提交`.env`。
2. 执行`python scripts/deployment_preflight.py --profile all --require-api --check-api`。
3. 执行Ruff、编译和全量测试。
4. 创建并校验备份，记录旧镜像标签和Git提交。
5. 通过CI构建Docker镜像。

### 10.2 启动后

1. 检查`/ready`和`/health`。
2. 检查`/metrics`能返回任务状态。
3. 创建测试项目、场景和小任务。
4. 确认任务只执行一次、成果可读取、审计记录存在。
5. 检查JSON日志中请求编号和任务编号可关联。

### 10.3 回滚

先回滚镜像。只有数据库变更不向后兼容或数据损坏时才恢复发布前备份。恢复在维护窗口完成，随后检查数据库、项目列表、历史任务和一个成果包。

## 12. 维护与扩展指南

新增页面业务规则应进入`src/core`或`src/application`，`app.py`只负责交互和展示。新增模型需要注册`ModelSpec`，实现统一结果结构，并增加黄金回归。新增输入字段要同时更新契约、验证、载荷版本、页面、接口测试和手册。

要扩展到高可用，优先实现PostgreSQL仓储适配器、专业任务队列适配器和S3成果存储适配器，不应让页面直接依赖具体数据库或云存储。迁移必须演练数据转换、幂等、租约语义和故障切换。

预测升级应保留时间顺序验证，禁止随机打乱未来数据进入训练集。复杂模型必须和当前透明基准比较，并记录训练区间、超参数、数据校验和与模型版本。

## 13. 常见故障处理

| 现象 | 判断 | 处理 |
|---|---|---|
| Community Cloud显示Oh no | 应用启动异常或依赖/代码错误 | 打开Manage app日志，定位首个异常；确认分支、入口和依赖 |
| 项目与任务显示单机演示 | 未配置独立API | 若只演示无需处理；完整部署时配置HTTPS API地址 |
| Push提示SSL/TLS handshake failed | 本机到GitHub的TLS连接失败 | 检查网络、代理和系统时间，恢复后重试，不要重复提交 |
| 快速模型不可行 | 约束过严或交换容量不足 | 放宽RPS/CO2/CEEP或提高容量后重算 |
| V17求解很慢 | 时间分辨率或场景数量高 | 演示改用60分钟，批量任务交给后台Worker |
| 15分钟数据不通过 | 缺列、时间错误、缺点或非法值 | 按字段、CSV行号和时间戳逐项修正 |
| 任务长期运行 | Worker失联或模型耗时 | 查`job_id`日志、心跳与租约；等待恢复或人工取消 |
| 恢复时数据库被占用 | API/Worker未停止或仍有文件句柄 | 进入维护窗口，停止进程后重新验证与恢复 |
