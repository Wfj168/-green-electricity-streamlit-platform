# 园区低碳规划与绿电直连优化平台项目交接手册

版本：0.8.0

交接重点：V17 综合能源规划

适用对象：产品负责人、演示人员、算法工程师、后端工程师、测试与运维人员

## 1. 项目定位与当前完成度

平台已经从单页算法原型升级为可单机演示、可单节点部署、可形成项目成果包的系统。主线不是展示预设图片，而是由用户配置参数后调用真实优化模型，再对容量、电量、成本、碳排、可靠性和场景差异进行解释。

当前已实现：

- V17 电、热、冷、气、储能、柔性负荷、碳和电转其他能源联合规划。
- S0—S8 九类规划场景和 R0—R4 固定容量运行场景的模型适配。
- 统一模型服务、稳定请求结构、模型版本、参数指纹和成果清单。
- 以人民币为唯一业务金额口径，主要业务页面中文化。
- 六标签运行分析、低碳核算、模型可信度审计和重复场景识别。
- 15 分钟数据契约、数据质量定位、透明基线预测和日内滚动请求。
- 项目、场景版本、数据集版本、模型版本、后台任务、结果和审计日志持久化。
- 接口服务、任务执行器、容器部署、令牌认证、健康检查、日志、备份与恢复。
- 自动编译、静态检查、部署预检、回归测试和镜像构建质量门。

尚未宣称实现：

- 多服务器高可用、企业单点登录、集中式任务队列和对象存储。
- 从企业生产数据库自动抽取并清洗实时数据的适配器。
- 配电网潮流、短路电流、继电保护、设备启停最小时间和施工图设计。
- 全生命周期碳排、碳信用、绿证抵消和真实市场交易结算。

## 4. V17 逐页操作与实现

### 4.1 平台概览

操作：

1. 在左侧“模型模式”选择“V17 综合能源规划”。
2. 查看当前状态；首次打开显示尚未运行，计算后显示当前结果。
3. 按“模型选型—系统配置—优化求解—决策交付”理解业务闭环。

实现：`app.py`根据`model_kind`切换导航，读取`integrated_result`会话状态；业务规则不写在概览页。

### 4.2 参数配置与运行

页面包含两个标签。

#### 模型参数与运行

默认选择 S4“低碳源荷储协同”。S0—S8 的含义如下：

| 场景 | 主要差异 |
|---|---|
| S0 | 无碳上限、无储能、无柔性负荷的基准 |
| S1 | 加入碳上限，并可将碳价计入目标函数 |
| S2 | S1 加电储能与蓄热 |
| S3 | S1 加日内柔性负荷 |
| S4 | 碳、储能和柔性负荷联合优化，推荐作为常规演示场景 |
| S5 | 增加偏远低空负荷、本地新能源支撑和孤岛保障筛查 |
| S6 | 增加产业园绿电覆盖、绿电直连目标和更强减排目标 |
| S7 | 组合低空、园区、微电网韧性和绿电直连约束 |
| S8 | 深度脱碳、电解槽和绿氢工艺热替代的内生优化 |

六类参数标签：

- 设备：光伏、风电、热电联产、热泵、电制冷、燃气锅炉容量上限。
- 储能：启用电储能和蓄热，设置能量及功率上限。
- 柔性负荷：设置日内可转移电量，可选可中断负荷。
- 碳约束：设置相对 S0 的年度排放上限和碳市场价格。
- 绿电直连：设置园区最低绿电覆盖、直连目标和新能源利用率。
- 电转其他能源与绿氢：设置工艺热替代、电解槽上限和新能源用电比例。

时间分辨率可选 60、30、15 分钟。演示和批量场景比较建议 60 分钟；正式项目在算力允许时使用 15 分钟并进行结果稳定性比较。随机种子用于让合成特征数据可复现，不代表实际天气预测。

点击“开始综合能源规划”后，配置先经过跨字段校验。例如未启用储能时储能上限不得作为有效规划容量；启用电转其他能源时，电解槽容量和替代目标必须互相一致。配置被序列化为“综合规划参数版本1”，并生成 SHA-256 参数指纹。

#### 数据校验与预测

15 分钟文件必填字段为时间戳、电负荷、光伏可用功率、风电可用功率和人民币电价；热负荷、冷负荷和温度可选。校验项包括：

- 必填列、数值类型和非负边界。
- 时间戳能否解析、是否严格递增、是否重复。
- 相邻时间是否为 15 分钟、是否缺点，并定位到文件行号。

预测模块严格按时间切分训练集和验证集，比较“同一时刻历史值”和“最近一天均值”两个透明基线，按平均绝对误差优先、均方根误差次优选择。日前预测固定生成 96 个点；日内请求携带预测版本和最新电、热储能状态，保证数据血缘。

注意：当前预测是可解释基线，不是生产级天气—负荷联合预测。接入企业数据后，可在保持`ForecastEvaluationResult`与`DayAheadForecast`返回结构不变的前提下替换算法。

### 4.3 运行分析

顶部八项指标来自同一次求解，不是页面静态数字。成果包按钮会下载原始工程表、中文结果表、输入场景、执行清单和版本元数据。

#### 综合看板

- 规划容量配置：展示各技术最优容量。
- 年度电量结构：展示发电、购电、售电、弃电等年度量。
- 成本对账：检查社会年度总成本与资本金年化、固定运维、燃料、电网购售电、储能损耗、柔性负荷、缺供惩罚和碳成本的关系。

#### 多能运行

选择六类典型日之一：春季灌溉、春秋光伏大发、夏季商业制冷、秋季农产品加工、冬季采暖、春节返乡。每个典型日带有代表天数，六类权重合计 365 天。图表分别解释：

- 电力供需：光伏、风电、热电联产、购售电、储能、电解槽和电负荷。
- 热力供需：热电联产、热泵、锅炉、蓄热、绿氢替代和热负荷。
- 冷量供需：电制冷和冷负荷。
- 储能状态：电储能和蓄热在典型日内的状态轨迹。

#### 经济性

所有金额以人民币计。资本成本通过资金回收系数年化：

`资金回收系数 = r × (1+r)^n ÷ ((1+r)^n - 1)`

其中`r`为折现率，`n`为寿命年限。社会年度总成本等于项目私有年度成本加碳外部成本；只有启用“在目标函数中计入碳成本”时，碳价才参与最优解选择。售电收入作为成本抵扣单列，不能将社会成本与项目现金流混为一谈。

#### 低碳分析

碳排放核算采用运营边界：

`年度排放 = Σ[典型日权重 × 时间步长 × (购电量×电网因子 + 热电联产燃气量×燃气因子 + 锅炉燃气量×燃气因子)]`

非 S0 且启用碳约束时，统一模型服务先以同一分辨率和随机种子运行 S0，再计算：

`年度目标 = min(S0年度排放 × 目标比例, 年度碳配额)`

目标被换算为模型使用的日均上限。页面展示排放来源、S0 基准、年度目标、当前结果、目标差距、减排率和平均减排成本。电转其他能源减排已经通过燃气替代体现在运行结果中，只作为贡献单列，不再次从总排放中扣除。当前未纳入设备全生命周期、绿证和碳信用。

#### 可靠性与约束

第一层检查能量平衡、服务保障、储能和购售电互斥等运行结果；第二层“模型可信度审计”检查：

- 价格、碳价和各技术单位造价是否处于筛查区间。
- 典型日权重是否合计 365 天，数据源是否明确为合成或实测。
- 电、热、冷平衡残差是否足够小。
- 成本分项、排放来源和总量能否对账。
- 多能服务率、未供能比例、利用率、弃电率和储能循环是否合理。
- 容量是否频繁顶到规划上限；若是，应扩大边界后重算。

“提示”不是模型失败，而是要求交付人员披露假设；“需核查”表示结果不能直接用于决策。

#### 数据明细

展示中文化的容量、调度、成本、碳、综合指标和诊断表。工程师调试时可在成果包的`data`目录查看原始字段；业务交付优先使用“结果表”目录。

### 4.4 场景与决策

#### S0—S8 场景对比

点击“运行真实场景对比”后，服务逐个调用 V17，不读取静态对比表。以 S0 为基准计算：

- 减排量 = S0 排放 − 当前场景排放。
- 减排率 = 减排量 ÷ S0 排放。
- 成本变化 = 当前社会年度成本 − S0 社会年度成本。
- 平均减排成本 = 成本变化 ÷ 减排量。

若平均减排成本为负，含义是在当前价格、造价和典型日假设下同时出现成本下降与减排，不等于已锁定收益。若多个场景的核心成本、排放、购电、弃电、储能循环和电解槽容量一致，系统标注“新增约束未改变核心结果”；演示时必须说明该约束在当前最优点未起作用。

#### 绿电直连与电转其他能源

V17 模式直接读取模型结果。三类绿电补充方案按目标电量、单位绿电成本、线路损耗和固定费用计算年度成本：园区内新增、虚拟电厂聚合、远端绿电基地专线。推荐项是三者中当前假设成本最低者，不包含接网批复、土地、融资、交易合同和税费的完整尽调。

电转其他能源内生优化把电解槽用电`P_ELZ`、绿氢供热`H_H2`和电解槽容量`C_ELZ`放入同一模型，并满足：

- 绿氢供热 = 电解槽用电 × 氢低位热值 × 氢锅炉效率 ÷ 单位制氢耗电。
- 电解槽功率不超过规划容量，也不超过当时光伏与风电出力。
- 年度用电不超过新能源发电量的设定比例。
- 启用最低工艺热替代时，年度绿氢供热必须达到目标。

### 4.5 项目中心

连接后台后，操作顺序为：创建项目—保存当前参数为场景版本—提交后台任务—查看任务—读取结果—下载成果。场景每次保存自动递增版本；相同幂等键的重试不会重复创建任务。

项目中心不是“未开发页面”。它在未配置后台时主动隐藏，以避免云端前端错误请求本机地址。数据库连接正确后会出现完整功能。

## 5. V17 核心算法

### 5.1 求解类型

核心位于`src/model/model_core_v17_3_1_county.py`，使用 SciPy 的 HiGHS 线性规划；启用严格充放电或购售电互斥时引入二进制变量并调用混合整数线性规划。主要决策包括设备容量、逐时出力、购售电、燃气、储能充放、电解槽用电、柔性负荷转入转出和非关键负荷未供能量。

### 5.2 目标函数

模型最小化年度化综合目标：

`年化投资 + 固定运维 + 燃气成本 + 购电成本 − 售电收入 + 需求费用 + 储能退化 + 柔性负荷成本 + 未供能惩罚 + 可选碳成本 + 平滑惩罚`

关键处理：

- 投资用资金回收系数年化，避免把一次性投资与年度运行费直接相加。
- 电、热、冷未供能采用不同的高惩罚价值，并设置年度期望未供能比例上限。
- 储能按充放电吞吐量计退化成本并限制年等效循环。
- 售电受接口容量、新能源年外送比例和总新能源建设约束，防止为卖电而无限扩建。

### 5.3 能量平衡

每个时间点分别建立电、热、冷平衡。

- 电侧供给：光伏、风电、热电联产发电、购电、储能放电、允许的未供电。
- 电侧消耗：电负荷、热泵、电制冷、电解槽、储能充电、售电和弃电。
- 热侧供给：热电联产供热、热泵、燃气锅炉、绿氢供热、蓄热放热、允许的未供热。
- 热侧消耗：热负荷和蓄热充热。
- 冷侧供给：电制冷和允许的未供冷；消耗为冷负荷。

热电联产、电制冷、热泵和锅炉都通过效率或性能系数把输入与输出关联。

### 5.4 储能

电储能状态递推为：

`本时段储能量 = 上时段储能量×留存率 + 充电功率×充电效率×步长 − 放电功率÷放电效率×步长`

蓄热采用同类方程。状态受最小、最大比例约束，每个典型日末回到初始比例，避免模型无偿消耗期末储能。严格互斥模式用二进制变量防止同一时段同时充放。

### 5.5 柔性负荷

可转移负荷在每个典型日内能量守恒，即转出总量等于转入总量；同时受最大转移比例和重叠限制。可中断负荷需显式启用并支付高额中断成本，默认关闭。

### 5.6 可靠性

关键负荷必须满足；非关键负荷允许以高惩罚暴露不足，而不是让模型直接无解。年度期望未供能比例默认不高于 0.01%。容量充裕度使用峰值需求、备用率和各电源容量信用进行筛查。

### 5.7 典型日年化

六个特征日权重分别为 55、65、75、60、80、30 天，总计 365 天。所有年度电量、燃料、成本和排放均按`数值×时间步长×代表天数`汇总。典型日适合方案筛查，但可能忽略连续极端天气和跨日储能，因此正式项目应补做全年 8760 小时验证。

## 6. 数据与合理性口径

### 6.1 当前演示数据

`src/model/data_profiles_v17_3_3_county_region.py`生成带农业灌溉、农产品加工、冷链、冬季采暖、返乡和低空终端特征的合成数据。它不是某个真实县域的运行记录。所有正式报告必须写明“合成特征数据”或替换为实测数据。

当前分时购电基础价为 300、520、430、850、350 元每兆瓦时，售电价按购电价的 35%生成；燃气价格约 245—290 元每兆瓦时燃气；碳价默认 215 元每吨二氧化碳。

### 6.2 2025 年筛查造价

| 技术 | 默认造价 |
|---|---:|
| 光伏 | 320 万元/兆瓦 |
| 风电 | 650 万元/兆瓦 |
| 热电联产 | 550 万元/兆瓦 |
| 热泵 | 120 万元/兆瓦热 |
| 电制冷 | 90 万元/兆瓦冷 |
| 燃气锅炉 | 40 万元/兆瓦热 |
| 电储能能量 | 90 万元/兆瓦时 |
| 电储能功率 | 70 万元/兆瓦 |
| 蓄热能量 | 20 万元/兆瓦时热 |
| 蓄热功率 | 15 万元/兆瓦热 |
| 电解槽 | S8 为 280 万元/兆瓦，通用默认 300 万元/兆瓦 |

这些值用于比较技术组合，不替代询价。光伏量级参考了宁夏吴忠 125 兆瓦光伏项目公开投资额和广东开平分布式屋顶光伏备案，并结合 IRENA 2024 年可再生能源成本报告作方向性校核。国家能源局公布的 2024 年全国光伏利用率为 96.8%，用于提醒演示结果不能长期维持完全无弃电的理想状态。

- [国家能源局 2024 年全国新能源并网消纳情况](https://www.nea.gov.cn/20250221/e10f363cabe3458aaf78ba4558970054/c.html)

### 6.3 正式项目标定顺序

1. 锁定项目边界、基准年和计量点。
2. 导入至少一年的电、热、冷、燃气和可再生能源数据。
3. 对齐计量周期、时区、缺失值、异常值和单位。
4. 替换当地购售电合同、基本电费、燃气和碳价。
5. 替换设备报价、寿命、效率、运维、融资和建设边界。
6. 用历史账单和能量平衡校核基准场景。
7. 运行参数敏感性、极端日和 8760 小时复核。
8. 通过可信度审计后再形成客户结论。

## 7. 成果包结构

V17 单场景成果包主要包含：

- `结果表/容量配置.csv`、`多能调度.csv`、`成本明细.csv`、`碳排放.csv`、`综合指标.csv`、`运行诊断.csv`：中文交付表。
- `data/*.csv`：保留原始字段的工程表。
- `scenario.json`：实际生效的场景参数。
- `metadata.json`与`execution.json`：平台版本、模型版本、场景、分辨率、随机种子、时间和执行摘要。

场景比较包另含总对比表、比较清单以及每个场景的完整成果包。成果文件的 SHA-256 校验值在后台结果记录中保存，用于确认下载文件未被替换。

## 8. 数据库接入现状

平台能够接入数据库，且项目模式已经实际使用数据库，不是概念页。当前 SQLite 表包括：

| 表 | 内容 |
|---|---|
| `projects` | 项目名称、负责人、状态和时间 |
| `scenario_versions` | 版本化输入参数 |
| `dataset_versions` | 数据版本、结构版本、校验值和存储地址 |
| `model_versions` | 模型名称、版本、引擎和代码提交号 |
| `optimization_jobs` | 请求、状态、进度、租约、重试和幂等键 |
| `optimization_results` | 摘要、指标、成果地址和校验值 |
| `audit_logs` | 操作人、动作、对象和明细 |

调用链为：前端—接口服务—仓储—数据库；任务执行器原子领取任务—统一模型服务求解—成果存储—同一事务写入结果与成功状态。

当前限制：数据集版本表已经存在，但 V17 当前主输入仍是场景参数加模型生成的特征曲线；尚未提供“选择数据库数据集并直接传给 V17”的业务适配器。下一阶段应新增`DatasetProvider`接口，把数据库或对象存储中的标准化时序转换为 V17 所需字段，再由统一模型服务注入，不应让求解器直接写数据库查询。

## 9. 部署、运维和安全

### 9.1 本地启动

```bash
pip install -r requirements.txt
streamlit run app.py
```

### 9.2 单节点项目部署

```bash
python scripts/deployment_preflight.py --profile all
docker compose up -d --build
```

服务包括前端 8501、接口服务 8000 和任务执行器。接口服务提供`/health`、`/ready`和`/metrics`。生产试点使用令牌认证，密钥和令牌只放环境变量或密钥服务，不提交仓库。

### 9.3 备份与恢复

备份同时保存 SQLite 数据库和成果文件，生成 SHA-256 清单。恢复前必须停接口服务与任务执行器，先执行仅校验，再在维护窗口强制恢复；覆盖前系统会生成回滚包。详见`deploy/README.md`。

### 9.4 任务可靠性

- 数据库事务保证只有一个执行器领取任务。
- 租约和心跳用于发现执行器异常。
- 未超过最大次数的过期任务重新排队；达到上限后失败并记录稳定错误码。
- 旧执行器不能覆盖新执行器完成的结果。
- 客户端重试必须复用幂等键。

## 10. 扩展路线

### 10.1 企业数据库

1. 定义统一时序字段、单位、时区和质量规则。
2. 实现数据库读取适配器，输出标准数据框和数据版本信息。
3. 将数据版本编号、校验值和时间范围写入执行清单。
4. 增加历史基准场景对账与数据血缘测试。

### 10.2 多节点生产

1. 将`PlatformRepository`适配到 PostgreSQL。
2. 将数据库轮询队列替换为 Redis 或专业任务队列。
3. 将本地成果目录替换为 S3 兼容对象存储。
4. 接入企业单点登录、角色映射、集中日志、指标和告警。
5. 增加无停机迁移、灾备恢复和容量压测。

### 10.3 模型深化

- 用实测 8760 小时和极端气象年复核典型日结论。
- 增加设备启停、最小开停机时间和分段效率后转为混合整数模型。
- 增加配电网拓扑、潮流和接入容量约束。
- 增加光伏、负荷、电价和碳价不确定性场景或鲁棒优化。
- 增加全生命周期碳核算和可验证的碳信用模块。

## 12. 交付前复盘清单

- 确认平台版本、模型版本、分支和提交号一致。
- 确认页面无欧元，业务金额均为人民币。
- 运行 S4，检查六标签分析、成果包和可信度审计。
- 运行 S0、S4、S8 对比，检查目标、减排、重复场景和负减排成本提示。
- 确认合成数据、典型日和当前碳边界已经披露。
- 执行编译、静态检查、部署预检和全部测试。
- 项目模式检查项目、场景、任务、结果、成果校验值和审计记录。
- 完成一次备份校验；正式交付前完成隔离目录恢复演练。
- 用客户实测数据、合同价格和设备报价完成正式标定后再发布商业结论。
