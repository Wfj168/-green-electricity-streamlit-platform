# 融合版 V2 数据模型说明

## 目标

V2 使用 PostgreSQL 作为项目级主数据库。现有 SQLite 继续服务当前 Streamlit 基线，不在融合版验收前迁移或删除。

## 主要数据域

1. 组织与园区：组织、园区、分区和时区。
2. 身份与权限：账号、角色、园区范围和有效期。
3. 资产与拓扑：能源资产、农业资产、父子关系和电气关系。
4. 测点与时序：测点、单位、方向、倍率、质量码、数据状态和接收时间。
5. 农业任务：四类任务、时间窗、功率边界、所需电量、中断约束和生产损失。
6. 绿电合同：合同容量、价格、输配费、辅助费、需量费、偏差考核、损耗和可用率。
7. 参数与证据：参数集、版本、来源等级、来源附件、适用期和不确定性区间。
8. 模型与场景：模型登记、代码提交、输入输出模式、场景和基线关系。
9. 任务与结果：优化任务、输入快照、校验和、指标、调度序列和能量流序列。
10. 碳与绿电：碳活动台账、排放因子、绿电来源去向和储能来源分账。
11. 运维与审计：告警、报告导出和前后状态审计日志。

## 可追溯链路

`页面指标 → 模型任务或实时测点 → 参数集/数据来源 → 来源证据 → 校验和与审计日志`

模型输出必须保存 `run_id`、`model_id`、`parameter_set_id` 和输入校验和。页面不得只保存最终数字。

## 金额与碳口径

- 合同、参数和结果金额统一使用人民币，数据库货币码固定为 `CNY`。
- 物理绿电、绿证和其他权益分别入账。
- 储能按光伏、直连、电网和不可核验四类库存分账。
- 直连送端注入、受端送达、线路损耗和中断分别记录。

## 时序扩展

首期使用 PostgreSQL 普通表加时间与 BRIN 索引，避免引入额外数据库依赖。测点量增长后可将 `measurements`、`energy_flow_intervals` 和相关账本迁移为 TimescaleDB 超表，业务主键和接口口径保持不变。
