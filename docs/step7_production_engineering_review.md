# 步骤7复盘：生产工程基础

## 阶段结论

本阶段完成了可部署、可交付的单节点生产工程闭环：后台任务具备幂等、原子领取、Worker租约、心跳、失败恢复与结果所有权保护；API具备请求追踪、就绪探针、指标和管理员审计；数据具备带校验清单的备份、验证、恢复和自动回滚备份。

当前阶段没有宣称跨主机高可用。PostgreSQL、Redis、对象存储、企业SSO和集中监控属于已定义边界的后续适配项。

## 实现清单

- 新增数据库迁移`002_job_leases.sql`，记录Worker、租约、心跳、尝试次数和幂等键。
- 用数据库事务原子领取任务，同一任务不能被两个并发Worker同时获得。
- 运行任务定时续租；租约过期后自动重排，达到最大次数后可诊断失败。
- 任务完成与失败写入校验Worker所有权，避免失联Worker回归后覆盖新结果。
- API为请求生成或透传`X-Request-ID`，API与Worker输出单行JSON日志。
- 新增`/ready`、Prometheus文本格式`/metrics`和管理员`/api/v1/audit`。
- 备份使用SQLite在线备份，清单包含平台版本、文件大小和SHA-256。
- 恢复前检查危险路径、ZIP、校验和与SQLite完整性；覆盖前自动生成回滚包。
- Compose接入Worker标识、租约时长和日志级别环境变量。

## 发现并修复的问题

Windows演练首次暴露SQLite连接句柄未关闭问题。Python的SQLite连接上下文本身只提交或回滚事务，并不会关闭文件句柄，导致恢复时无法替换数据库。数据库连接现改为离开上下文时提交/回滚并关闭，随后备份恢复和全部持久化测试均通过。

隔离恢复命令第一次调用时，PowerShell将通配符作为普通文件名处理，因此没有进入产品恢复逻辑。修正命令选取方式后，备份校验和隔离恢复成功。该问题不影响平台代码，但已作为演练操作注意项记录。
