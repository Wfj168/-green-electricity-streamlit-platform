# 第一阶段参数治理与数据模板说明

## 1. 实现目标

第一阶段建立唯一参数注册表。模型、页面和成果报告不再分别保存绿电成本、损耗、碳价、造价和设备技术参数。所有参数均包含中文名称、单位、当前值、上下限、来源等级、核验状态、来源说明和设置方法。

程序注册表位于`src/core/agri_parameter_registry.py`，可交接参数台账位于`data/templates/phase1_parameter_ledger.csv`。

## 2. 来源等级

| 等级 | 含义 | 示例 |
|---|---|---|
| A | 计量实测 | 园区总表、分项电表、能源管理系统15分钟数据 |
| B | 合同、铭牌、报价和批复 | 绿电合同、供电合同、设备铭牌、接入批复、供应商报价 |
| C | 政府和官方 | 正式电价通知、官方碳排放因子、气象资料 |
| D | 工程计算 | 光伏可建容量、泵站功率、工艺能耗、设备效率校准 |
| E | 演示假设 | 当前V17中尚未由项目资料替换的参数 |

来源为E或状态不是“已核验”的参数不能用于正式投资和零碳结论。平台后续将显示正式就绪缺口，不因参数已有默认值而隐藏风险。

## 3. 当前统一的绿电直连演示值

| 方式 | 度电成本/元每兆瓦时 | 损耗率 | 固定费用/万元 |
|---|---:|---:|---:|
| 园区内新增绿电 | 320 | 1.5% | 600 |
| 聚合绿电 | 395 | 2.5% | 900 |
| 外部绿电基地直连 | 355 | 3.5% | 1800 |

这些数字只是统一后的演示基线，不代表同江实际合同价格。V17场景、快速页面和绿电服务现在从同一个注册表读取，不再保留360/430/390元每兆瓦时的第二套页面默认值。

## 4. 四套数据模板

### 4.1 15分钟时序模板

`data/templates/phase1_agri_park_timeseries_template.csv`

必须包含四类负荷、园区总表、光伏可用出力、直连绿电可用功率、购售电价、电网排放因子、质量标记和来源。四类分项负荷之和需要与总表对账。

### 4.2 设备模板

`data/templates/phase1_agri_park_assets_template.csv`

保存泵站、烘干机、加工设备、冷库、变压器、光伏和储能的铭牌参数、运行边界与来源。

### 4.3 生产任务模板

`data/templates/phase1_agri_park_tasks_template.csv`

保存最早开始、最晚完成、运行时长、功率范围、所需电量、产品数量和必须完成状态。后续优化不能只平移固定负荷，必须证明农业任务完成。

### 4.4 来源资料模板

`data/templates/phase1_source_ledger_template.csv`

记录每份账单、合同、铭牌、报价、政府文件和工程计算书的名称、版本、生效日期、责任方、存储位置和核验状态。

## 5. 正式数据缺口

当前尚未具备以下正式项目值：

- 四类负荷的年电量、峰值和连续15分钟数据。
- 园区变压器容量、功率因数和并网批复。
- 光伏可用面积及工程可建容量。
- 绿电直连通道容量、可用出力和合同价格。
- 正式购售电价、需量电费和碳排放因子版本。
- 设备铭牌、报价、效率曲线和农业生产任务。

因此当前平台仍只能运行“可追溯演示基线”。下一步将基于统一模板重建农业园区分项负荷和全年时序，并明确每一项演示负荷的设置公式。

## 6. 本步骤整改结果

- `PARAM-001`已解决：建立唯一参数注册表、来源等级、核验状态和可导出的参数台账。
- `PARAM-002`已解决：V17场景、快速绿电页面和绿电服务统一读取320/395/355元每兆瓦时的同一套演示值。
- 参数台账完整不等于正式数据齐备；来源为E或状态为“待补充”的参数仍会进入正式就绪缺口。
