# 生产工程与运维边界

## 当前已实现的交付拓扑

当前版本支持一个UI、一个API、一个或多个同节点Worker和一个持久化数据卷。API保存项目、场景、任务、审计和结果索引，Worker调用统一模型服务，成果包写入本地文件存储。SQLite运行在WAL模式，适合单服务器受控试点和中小规模项目交付。

## 任务可靠性算法

任务提交可携带项目级`idempotency_key`。数据库唯一索引保证同一项目中的相同键只对应一个任务，即使客户端因超时重试，也不会重复创建。

Worker使用`BEGIN IMMEDIATE`事务原子选取最早的排队任务，并在同一事务内写入`worker_id`、租约截止时间和尝试次数。运行期间心跳按不超过30秒的间隔续租。若Worker退出，其他Worker会把过期任务重新排队；达到最大尝试次数后任务转为失败。任务完成和失败写入都校验Worker所有权，因此旧Worker恢复后不能覆盖新Worker的结果。

## 可观测性

- API为每个请求生成或透传`X-Request-ID`，并记录方法、路径、状态码与耗时。
- Worker按`job_id`和`worker_id`记录领取、成功和失败事件。
- `/health`返回应用与模型信息，`/ready`验证数据库可用性，`/metrics`按状态输出任务数量。
- 管理员审计接口返回项目、场景、任务的关键动作记录。

当前指标端点采用Prometheus文本格式，但仓库不内置Prometheus、Grafana或告警平台。交付环境应由运维系统采集，并至少为API不可用、Worker持续无心跳、失败任务增长、磁盘空间不足和备份失败配置告警。

## 备份恢复算法

在线备份使用SQLite Backup API获得一致性数据库副本，随后把数据库与成果文件写入ZIP。清单记录平台版本、时间、每个文件大小和SHA-256；校验阶段同时执行ZIP完整性检查、路径穿越检查、文件校验和与SQLite`integrity_check`。

受控恢复会先完整校验输入备份。覆盖现有数据时，系统先自动创建发布前回滚包，再用同目录临时文件原子替换数据库。恢复必须在API与Worker停止的维护窗口执行。

## 安全边界

当前令牌模式提供管理员、工程师、只读角色和所有者数据过滤，适合受控试点。签名密钥、启动密钥和短期令牌只能通过部署环境注入。正式企业交付仍需接入客户SSO、MFA、集中身份生命周期、密钥托管、TLS终止与网络访问控制。

## 高可用扩展路径

以下组件是明确的后续扩展，不属于当前已交付能力：

1. 用PostgreSQL仓储实现替换SQLite仓储，保留现有项目、场景、任务与审计领域接口。
2. 用Redis或专业任务队列替换数据库轮询，同时保留幂等键、租约、重试和结果所有权语义。
3. 用S3兼容对象存储替换本地成果目录，并为成果下载增加短期签名地址。
4. 在多实例API前增加负载均衡、TLS和集中会话外的无状态认证。
5. 通过OpenTelemetry/Prometheus集中采集日志、指标和链路。

只有上述适配器完成集成测试、故障切换演练和数据迁移演练后，才能把系统标记为跨主机高可用。
