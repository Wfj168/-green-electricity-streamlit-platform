# 步骤6复盘：15分钟数据、预测与滚动运行

## 结论

本阶段门禁通过。平台已建立15分钟数据从上传、质量检查、基准评估、日前96点预测到日内滚动请求的最小闭环。当前预测能力定位为可复现基准框架，不把未经验证的复杂模型包装成生产预测。

## 15分钟数据契约

必填列及单位：

- `timestamp`：ISO-8601时间戳；
- `electric_load_mw`：电负荷/MW；
- `pv_available_mw`：光伏可用功率/MW；
- `wind_available_mw`：风电可用功率/MW；
- `electricity_price_cny_per_mwh`：电价/CNY-MWh。

可选列包括热负荷/MWth、冷负荷/MWc和环境温度/摄氏度。质量检查覆盖缺列、时间格式、重复时间、非递增时间、非15分钟间隔、缺失数据点、非数值和负能源值。问题记录包含错误码、严重级别、字段、CSV行号、时间戳和修复说明。

## 预测评估

当前实现两个透明基准：

1. `seasonal_naive`：使用前一日同一15分钟时刻的值。
2. `recent_mean`：使用最近96点均值。

平台在独立验证区间计算MAE、RMSE和sMAPE，按MAE/RMSE选择表现更好的模型。页面明确展示两者对比、训练起止时间、验证起止时间和选型结果。未来接入机器学习模型时必须在相同验证区间优于或明确对比这些基准。

## 日前与日内接口

- 日前预测固定输出96个15分钟点。
- 预测版本由算法、目标列、训练截止时间、预测开始时间和预测长度生成稳定指纹。
- 日内请求固定引用预测版本，包含R0—R4运行场景、15分钟间隔、滚动窗口和完整96点预测。
- 电储能和蓄热最新SOC以0—1比例传入V17的`bat_initial_soc`和`ts_initial_soc`，不会默认为上一场景的静态值。
- 请求使用`intraday-rolling-v1`结构，可下载JSON并在后续生产任务层持久化。
