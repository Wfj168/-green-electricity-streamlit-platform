# 园区低碳规划与绿电直连优化平台 v0.7.0 逐页面演示讲稿

## 1. 演示前5分钟检查

1. 提前打开平台网址并等待首页完整出现，避免Community Cloud休眠唤醒占用演示时间。
2. 确认侧栏可切换“快速电力滚动调度”和“V17综合能源规划”。
3. 快速模式先用默认参数运行一次；综合模式先用S4、60分钟、随机种子42运行一次。
4. 数据页提前加载14天示例并生成预测。正式讲解时仍可重新点击，但已有结果可作为网络或求解延迟时的备用。
5. 若完整后台未部署，确认“项目与任务”显示单机演示模式。讲解时明确这是Cloud只部署UI的正常状态。
6. 关闭无关标签页和通知，浏览器缩放保持100%，准备一个本地成果ZIP作为下载备用。

## 2. 15分钟主线演示

### 2.1 开场：平台概览，约1分钟

操作：打开“平台概览”，侧栏保持“快速电力滚动调度”。

讲稿：

“这是园区低碳规划与绿电直连优化平台。它不是一张预先制作的结果大屏，而是把模型选择、参数配置、优化求解、指标校核、方案比较和成果导出串成一个可复现流程。平台目前有两类模型：第一类是快速电力滚动调度，适合快速分析风光、气电、电网和储能；第二类是V17综合能源规划，进一步联立电、热、冷、气、储能、柔性负荷、碳约束和P2X。页面上的结果都来自当前求解，参数变化后需要重新运行。”

指向“业务流程”四张卡：

“整个工作流是模型选型、系统配置、优化求解和决策交付。后台部署后，还可以把每次参数保存成场景版本并形成可追溯任务。”

### 2.2 快速模式配置，约2分钟

操作：进入“参数配置与运行”。

讲稿：

“这里先定义园区的系统边界。基础场景包括年用电需求、规划周期、滚动天数、购售电价格和电网交换容量。下面三组政策约束分别是最低绿电占比、年度碳排上限和最大弃电率。设备、储能、燃料和投资成本都可以编辑。源荷数据既可以上传8760小时CSV，也可以由平台生成可复现的典型曲线。”

操作：保持默认参数，指向“允许自动规划”，点击“开始实时优化调度”。

讲稿：

“模型会先做容量预规划，再使用线性规划进行滚动调度。每次看未来48小时，但只保存前24小时执行结果，下一窗口继承前一窗口末端SOC。这能避免每天独立计算导致储能状态断裂。”

等待完成后：

“四张结果卡已经由本次求解刷新，说明参数、模型和后续页面已经形成闭环。”

### 2.3 快速结果与约束，约2分钟

操作：进入“实时结果图”。

讲稿：

“第一张图展示负荷如何由风光、气电、购电和储能共同满足。储能图展示充放电与SOC，供需平衡图用于检查每个时段的能量守恒，购售电响应图把价格和电网交换放在一起。展开明细可以追溯到逐小时数据。”

操作：进入“调度综合指标”。

讲稿：

“这里不是只给一个成本数字，而是把经济、低碳、可靠性和约束执行放到同一页。RPS、CO2和弃电率会逐项显示目标、结果和是否满足。下方滚动日志保留每个48小时窗口的目标值和保存段末端SOC，因此可以验证滚动算法确实执行。”

### 2.4 绿电直连与导出，约2分钟

操作：进入“绿电直连规划”。

讲稿：

“平台先把当前滚动结果折算为年度用电和年度绿电，再计算目标绿电占比下的缺口。三类补充方式分别是园区内新增、虚拟电厂聚合和绿电基地专线。成本计算同时考虑电量、LCOE、规划年数、损耗和固定工程费。系统给出最低成本筛选结果，但工程落地还要进一步核对土地、线路走廊、电网接入和合同条件。”

操作：进入“结果导出”。

讲稿：

“一次计算可以导出输入、源荷时序、逐时调度、容量规划、指标、滚动日志和图表。项目交付时我们保存成果包，而不只保存页面截图，这样可以追溯平台版本、模型版本和场景输入。”

### 2.5 V17综合规划，约3分钟

操作：侧栏切换“V17综合能源规划”，进入“参数配置与运行”。

讲稿：

“综合模式以S0到S8模板组织不同技术和政策路径。S0是基准；S1加入碳约束；S2、S3分别增加储能和柔性负荷；S4形成低碳源荷储协同；S5增加偏远低空微电网韧性；S6增加产业园区净零约束；S7综合低空、园区和绿电直连；S8进一步把P2X和绿氢作为优化内生决策。”

操作：选择S4、60分钟、随机种子42，依次点开设备、储能、柔性负荷、碳约束、绿电直连和P2X标签。

讲稿：

“页面参数不是简单覆盖显示，它们会合并为带结构版本的请求，执行范围和跨字段依赖校验，并生成参数指纹。演示使用60分钟以控制时间，正式研究可以选择30或15分钟。”

操作：点击“开始综合能源规划”。

讲稿：

“模型联立规划容量与典型日运行。目标函数包含年化投资、固定运维、燃料、购售电、需量、储能退化、柔性负荷、弃能、缺供，以及启用时的碳成本。电、热、冷平衡和设备转换效率在同一模型中求解。”

### 2.6 多能流与综合指标，约2分钟

操作：进入“多能流结果”，选择一个典型日。

讲稿：

“这里展示一个带年度权重的典型日。电平衡、热平衡、冷平衡和电/热储能状态来自同一次求解。下面的容量、调度、成本、碳排和诊断表保留原始结果。年度指标使用典型日权重折算，不能把单日曲线直接当作年度总量。”

操作：进入“综合规划指标”。

讲稿：

“指标按能源、经济、环境、可靠性和园区与P2X分组。经济口径中特别区分私人年成本、碳外部成本、社会总成本和目标函数成本；可靠性侧用多能服务率、缺供和约束诊断检查方案是否只是低成本但不可用。”

### 2.7 数据预测与场景比较，约2分钟

操作：进入“数据与预测”，点击“加载14天示例数据并检查”，再点击“评估基准并生成日前96点预测”。

讲稿：

“生产运行首先要求数据可用。契约会检查必填列、单位、重复时间、缺失点、15分钟间隔、数值和非负约束，并把错误定位到CSV行和时间戳。预测部分先比较前一日同刻的季节朴素法和最近96点均值法，用MAE、RMSE和sMAPE评估，再自动选择验证集更优的基准并生成带版本号的日前96点预测。日内请求继续继承预测版本和最新电、热储能SOC。”

操作：进入“场景对比”，现场时间紧时只选择S0、S4和S8，保持60分钟，点击“运行真实场景对比”。

讲稿：

“场景比较会逐个调用同一个V17模型，而不是读取一张写死的表。平台以S0为基准计算减排量、成本变化和平均减排成本，并把每个场景的原始成果包一起导出。完整评审可运行全部S0到S8。”

### 2.8 收尾：工程架构，约1分钟

操作：进入“工程架构”。

讲稿：

“工程上，页面只负责交互；应用服务负责双模型路由、预测和比较；核心模块负责契约与验证；模型层负责求解；API、数据库和Worker负责项目化任务；日志、指标和备份恢复负责运维。后台任务通过幂等键、原子领取、租约心跳和旧Worker写保护避免重复执行。当前版本是单节点可交付系统，跨主机高可用仍需接入PostgreSQL、专业队列、对象存储和企业SSO。”

结束语：

“平台的核心价值是把多能规划算法变成可配置、可追溯、可比较和可交付的工程流程。它给出方案筛选与运行决策依据，同时清楚保留了接入审查和详细工程设计的专业边界。”

## 3. 全页面扩展讲稿

### 3.1 项目与任务页补充讲法

若显示单机演示模式：

“当前网址使用Community Cloud的UI部署，因此实时计算和导出正常，项目版本与后台历史暂未启用。这不是报错。完整交付会独立部署API和Worker，并把HTTPS后台地址注入前台。不能把127.0.0.1写成云端后台，因为那只指向云容器自身。”

若后台已连接：

“项目是业务隔离边界，场景是不可变版本，任务记录模型、状态、尝试次数和时间，结果记录摘要、指标、成果地址和校验和。客户端网络重试会复用幂等键，Worker失联后由租约机制恢复任务。”

### 3.2 S0—S8逐场景一句话

| 场景 | 现场一句话 |
|---|---|
| S0 | “先建立没有额外低碳技术的基准成本和基准排放。” |
| S1 | “单独观察碳约束和碳价带来的变化。” |
| S2 | “在低碳约束上加入电储能和蓄热，看储能贡献。” |
| S3 | “不用储能增量，单独观察柔性负荷贡献。” |
| S4 | “把碳、储能和柔性负荷放在同一优化中协同。” |
| S5 | “增加低空作业负荷、本地新能源和孤岛时长约束。” |
| S6 | “强化产业园绿电覆盖、新能源利用率和碳上限。” |
| S7 | “把低空、产业园、微电网和绿电直连综合展示。” |
| S8 | “在更严脱碳目标下把电解槽和绿氢纳入内生优化。” |

### 3.3 结果指标解释模板

“先看可行性和可靠性，再看能源结构，然后看经济与碳。若服务率或平衡诊断不通过，低成本没有决策意义；若可行，再比较年度购电、新能源利用率、碳排和社会年成本。场景之间使用同一随机种子和时间分辨率，保证比较口径一致。”

### 3.4 为什么使用线性规划

“园区规划需要同时处理大量时段、设备和约束。线性规划可解释、可复现、求解稳定，适合方案筛选。只有在强制充放电互斥或购售电互斥等离散逻辑出现时才使用混合整数模型。这样在精度、速度和可维护性之间取得平衡。”

### 3.5 为什么先用基准预测

“预测模块先建立透明基准，不急于使用复杂模型。任何高级算法都必须在同一时间顺序验证集上显著优于基准，才能证明增加复杂度有价值。这样可以防止数据泄漏和只展示训练集效果。”

## 4. 现场常见问答

### 4.1 这些数字是不是写死的

答：“不是。快速模式、V17单场景和场景比较都调用实际模型。页面只读取当前结果。场景比较的ZIP还包含每个场景原始成果，可以复核。”

### 4.2 为什么刷新后结果没了

答：“Community Cloud的单会话结果存在浏览器会话中，刷新可能丢失。完整部署把项目、场景、任务和成果持久化，刷新后可重新查询。”

### 4.3 能否直接控制现场设备

答：“当前定位是规划与调度决策平台，不直接下发控制指令。接入EMS或SCADA前还需要实时接口、安全联锁、权限审批和故障回退。”

### 4.4 能否替代潮流和接入审查

答：“不能。当前是多能量平衡与经济低碳优化，需要在工程阶段补充节点网络、潮流、电压、短路、保护和接入校核。”

### 4.5 为什么场景对比有时较慢

答：“因为它依次执行多个真实优化，不是读取静态表。演示可用60分钟和S0/S4/S8，正式评审再运行全部九个场景或交给后台Worker。”

### 4.6 如何保证后台任务不重复

答：“任务提交有项目级幂等键，领取在数据库事务中完成，运行时有租约和心跳，写结果还要校验Worker所有权。网络重试、并发Worker和失联恢复都有明确规则。”

### 4.7 数据如何保证可追溯

答：“场景有版本和参数指纹，模型有版本，预测有版本，成果包有执行清单，后台结果有URI和SHA-256，关键操作写入审计日志。”

### 4.8 当前能否称为生产级高可用

答：“当前是可部署、可交付、可维护的单节点生产基础，不是跨主机高可用。高可用要继续接入PostgreSQL、专业任务队列、对象存储、SSO和集中监控，并完成故障切换演练。”

## 5. 故障应急讲稿

### 5.1 平台出现Oh no

先说：“云端应用正在恢复，我先用本地已导出的成果说明结果结构。”随后打开Streamlit Manage app日志，定位第一个异常。不要在观众面前连续刷新，也不要临时修改Secrets。

### 5.2 项目与任务显示原型/单机模式

直接说明Cloud部署边界，继续演示其他页面。这个页面的降级不会影响单会话求解、图表、指标和导出。

### 5.3 模型不可行

先保留错误提示并解释：“平台没有用假结果掩盖不可行约束。”快速模式放宽RPS、CO2或CEEP，或提高交换容量；V17恢复S4默认参数和60分钟后重算。

### 5.4 场景比较来不及

改选S0、S4、S8，使用60分钟。若仍超时，展示已保存的对比成果包，并明确这是此前由同一版本真实模型生成的结果。

## 6. 演示结束后的交付动作

1. 保存本次使用的场景参数、模型版本和成果包。
2. 记录演示中提出的问题、负责人和截止时间。
3. 若要让客户直接使用“项目与任务”，安排独立API/Worker部署与HTTPS地址。
4. 在推送升级分支后创建面向`main`的PR，等待CI测试与Docker镜像构建通过。
5. 合并并重新部署后，再用公开网址按本讲稿执行一次验收演示。
